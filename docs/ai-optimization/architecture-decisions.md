# 关键技术决策（ADR）

> 只记录「为什么这样改」以及「以后不要怎样改」。每条都写明代价与替代方案。

## ADR-001 · 数据损坏时「隔离并继续」，而不是拒绝启动
- 背景：一条 `null` 记录会让进程退出；结构不合法会让空库覆盖原文件且没有副本。
- 决策：任何 store 在读取失败或包含坏记录时，先把原文件复制为 `<store>.corrupt-<ts>`，再用可用记录继续服务；
  损坏会话缺 `messages` 归一为 `[]`；损坏场景下跳过「空库日备份」。
- 代价：进程会带着不完整数据继续跑，用户看到「少了几个对话」。可接受的替代方案是拒绝启动，但那会让整个产品不可用。
- 替代方案（未采用）：只读降级 + 恢复向导。需要 UI，排期到后续。
- 不要这样做：把 `.corrupt-*` 当垃圾删掉；或在没有副本的情况下覆盖主文件。

## ADR-002 · 项目必须有 owner，即使默认只有一个人
- 背景：`singleUser:false` 是文档承诺的模式；项目此前是全局命名空间，可被任意已登录设备改名/删除/继承权限。
- 决策：项目记录携带 `owner`；所有读取与写入经 `ownedProject(id,res,owner)`；他人项目一律 404（不区分「不存在」与「不是你的」）；
  单用户模式启动时把历史项目归属到 `single-user-owner`。
- 代价：`projects.json` 多一个字段，旧数据需要一次启动归属（已实现且幂等）。
- 不要这样做：用「存在性检查」代替归属检查；或用 403 暴露资源存在性。

## ADR-003 · 导航身份（conversationId）必须在每个 await 之后重新校验
- 背景：上传、创建会话、attach 握手都是秒级异步；期间用户可能切换对话。此前会把 A 的气泡/回答画进 B，或把消息发给 A 却显示在 B。
- 决策：`submitComposer` 捕获目标会话并在上传后校验；`ensureConversation` 在用户已导航时返回 `null`；`attachRun` 用递增的 `attachSeq` + `currentId` 双重门禁；`openConversation`/`newChat` 递增序号使在飞握手失效。
- 代价：多几处显式判断；`sendMessage` 需要处理 `null`。
- 不要这样做：用「先渲染再纠正」的方式处理跨会话流；那会让用户看到错误内容并且无法撤销。

## ADR-004 · 会话线程不是 live region
- 背景：`#thread` 曾是 `role="log"`（隐式 `aria-live=polite`），而流式渲染每 60–280ms 整体替换一次 DOM。
- 决策：线程改为 `role="region" aria-label="对话内容"`，语义里程碑（开始/完成/授权）由 `#srStatus` 播报。
- 代价：读屏用户不再逐段听到流式正文。这是刻意的：逐段播报在整体重绘下会变成噪音。
- 替代方案（未采用）：改成增量 append 以保留 `role=log`；这需要重写渲染器，收益不足以抵消风险。
- 不要这样做：为了「语义正确」把 `role=log` 加回去而不改渲染方式。

## ADR-005 · 存储不可用时降级到内存，而不是白屏
- 背景：站点数据被禁用时 `localStorage` 访问直接抛 `SecurityError`，而客户端在模块初始化就读取它，导致登录表单都没装上。
- 决策：三个前端模块各自持有安全 storage 包装（探测失败退化为内存 Map），所有读取/写入走包装。
- 代价：该场景下草稿/主题等不持久，刷新即丢；这是可接受的降级。
- 不要这样做：在顶层直接 `localStorage.getItem(...)`。

## ADR-006 · 配额与容量只统计「还有效」的东西
- 背景：已撤销的分享仍占用 100 条上限 30 天，导致撤销后仍然不能再分享；满库时重复导入被 409 拒绝。
- 决策：分享配额只统计未撤销且未过期；导入容量检查移到去重之后；记忆满时拒绝而不是淘汰旧记忆。
- 代价：统计逻辑稍微复杂；极端情况下「已撤销但仍保留快照」的磁盘占用与配额脱钩（可接受）。
- 不要这样做：用「删除数据」来腾出配额。

## ADR-007 · 后台 I/O 不得阻塞请求路径
- 背景：purge 会在请求线程里同步解析并重写每个日备份（156MB 库阻塞 1.5–2.2s）。
- 决策：备份清理改为异步 + 临时文件 + rename；所有 `void this.flush()` 都挂 `.catch`；失败写日志而不是静默。
- 代价：purge 返回时备份可能尚未清理完（最终一致）。
- 不要这样做：为了「立刻一致」把大文件同步读写放回请求路径。

## ADR-008 · 静态度量必须从唯一来源派生
- 背景：`static.mjs` 自维护一份 CSS 清单，漏掉了 `evolution.css`/`sidebar.css` 共 44KB，预算形同虚设。
- 决策：预算从 `server/index.mjs` 的 `CSS_BUNDLE_FILES` 解析；并新增「孤儿样式表」检查（既不在 bundle 也无人引用 → 失败）。
- 代价：静态检查依赖源码文本格式（用正则解析数组），格式大改会失败并提示。
- 不要这样做：再复制一份清单。

## ADR-009 · 可访问性阈值用实测值判定，不用主观描述
- 背景：选中行次要文字曾是两个主题下都不达标的 4.40:1 / 4.11:1。
- 决策：`--text-3` 调整为 #64646a / #a8a8ae；验收以「渲染后前景/背景合成对比度」实测为准（4.81 / 4.80）。
- 代价：整体晦暗文字略深/略亮，视觉层级差异变小。
- 不要这样做：只看 CSS 变量名判断对比度。

## ADR-010 · 不为通过审计而修改契约
- 背景：审计会指出「测试断言旧选择器」「角色语义」等问题。正确做法是更新断言到**新契约**，而不是删掉断言或回退功能。
- 决策：`projects.mjs` 改为断言下拉契约并补触摸上下文；`cycle1` 改为断言「非 live 的具名区域」；新增套件覆盖新行为。
- 代价：测试与实现必须一起演进。
- 不要这样做：把失败的断言改成 `true`。
