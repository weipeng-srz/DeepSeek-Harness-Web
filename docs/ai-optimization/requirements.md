# 需求池与验收标准

> 由审查发现转换而来。每条需求都有：价值、成本、风险、依赖、验收标准、当前状态。
> 排序原则：先 P0（数据/安全/可用性），再 P1（高频缺陷、体验障碍），再 P2/P3。
> 状态：`DONE` 已交付并验证 · `OPEN` 待做 · `DEFERRED` 明确延期。

## 优先级定义

| 级别 | 定义 | 本轮要求 |
| --- | --- | --- |
| P0 | 数据丢失/损坏、越权、启动失败、核心流程不可用 | 必须修复并验证 |
| P1 | 高频功能缺陷、明显体验障碍、工程基线失效 | 计划内修复 |
| P2 | 交互/视觉/工程质量改善 | 按收益排序，能验证才做 |
| P3 | 细节打磨、长期架构改进 | 记录，不强行做 |

---

## R-01 `DONE` 会话数据损坏的恢复能力（P0）
- 价值：一次坏记录 = 全部对话不可用，是本项目唯一的单点致命风险。成本：中（5 个 store）。风险：低（只增不改语义）。
- 验收：①`conversations:[null,…]` 能启动且列表 200，坏记录被隔离；②结构非数组时原文件复制为 `.corrupt-<ts>`；③缺 `messages` 不再 500；④损坏后不生成空库日备份。
- 证据：`tools/qa/store-contract.mjs` 7/7。

## R-02 `DONE` 项目按 owner 隔离（P1）
- 验收：`singleUser:false` 下 B 对 A 的项目 `GET/PATCH/DELETE/purge/restore/files` 全部 404；B 的列表/备份不含 A 的项目；B 不能在 A 的项目里建对话。
- 证据：`tools/qa/isolation.mjs` 17/17。

## R-03 `DONE` 导航竞态不再串对话（P0/P1）
- 覆盖：上传中切换、创建中切换、attach 回放、回复中切换、失败发送。
- 验收：任何切换后，旧对话的消息/回答/停止按钮都不出现在新对话；输入框与暂存附件不丢、不串。
- 证据：`tools/qa/client-behaviour.mjs` 20/20。

## R-04 `DONE` 焦点与键盘安全（P1）
- 验收：审批到达时焦点仍在输入框且回车不授权；菜单 Escape 只关菜单；回收站参与焦点陷阱且关闭后焦点回到触发控件；命令面板动作后焦点不落到 body。
- 证据：`client-behaviour.mjs`、UX 审计复跑（`afterEscape.activeId=trashBtn`）。

## R-05 `DONE` 降级可用性（P1）
- 验收：禁用 localStorage 时登录页可见、可登录、无 pageerror。
- 证据：`client-behaviour.mjs`「blocked localStorage…」。

## R-06 `DONE` 可读性与触控（P1/P2）
- 验收：①320px 滚动时顶栏有实底，正文不与图标重叠；②会话标题在无侧栏时可见；③选中行次要文字对比度 ≥4.5:1；④coarse 指针下会话行/工具按钮/模型 chip ≥44px；⑤导出/导入不被挤成竖排。
- 证据：320px 探针（`bg srgb 1 1 1 / 0.88`、标题 106×44）；对比度实测 4.81/4.80。

## R-07 `DONE` 静态预算与样式交付可验证（P2）
- 验收：`static.mjs` 从 `CSS_BUNDLE_FILES` 派生预算；新增孤儿样式表会失败；预算数字与线上一致（303KB/320KB）。
- 证据：`node tools/qa/static.mjs` 8/8。

## R-08 `DONE` 请求体上限与文档一致（P2）
- 验收：24,000 汉字可发送；超过 24,000 字符 → 400 且提示字符上限；非聊天接口仍保持 64KB 上限。
- 证据：`api.mjs`（既有）+ 手工 24000 字符请求 200/流式开启。

## R-09 `DONE` 分享/记忆/通知的边界行为（P2）
- 验收：①撤销后的分享不再占配额；②记忆满时导入不删除旧记忆并返回 `full:true`；③被拒的 notify PATCH 不改变运行态；④负数有效期 400、0 仍表示长期。
- 证据：后端复跑脚本；`store-contract` 记忆用例。

## R-10 `DONE` QA 基线可解释（P1）
- 验收：`node tools/qa/run-all.mjs` 全绿；新增套件覆盖损坏数据、越权、导航竞态；历史漂移断言更新到新契约。
- 证据：**20/20 suites passed**。

## 延期项（`DEFERRED`，附理由）

| ID | 需求 | 理由 | 若要做的第一步 |
| --- | --- | --- | --- |
| R-20 | 会话存储改为「一会话一文件 + 索引」 | 数据模型迁移，涉及导入/备份/去重/回收站全部路径；本轮没有足够验证预算，贸然改会直接威胁 R-01 的成果 | 先写迁移脚本 + 双读单写灰度 + 回滚开关 |
| R-21 | 搜索索引（写入时维护搜索块） | 依赖 R-20 的写入路径；当前 11ms@36MB 尚不影响体验 | 与 R-20 同批做 |
| R-22 | brotli（实测可省 16.3KB / -7.9%） | 纯收益但需协商 + 缓存改造 | 加 `Accept-Encoding: br` 分支与 per-asset 缓存 |
| R-23 | codex 模块按需加载（-13KB 冷载） | 需要处理首次切换的闪烁与加载态 | 用 dynamic import + 骨架 |
| R-24 | 深链定位 2000 条以前的回答 | 需 `around=<id>` 分页语义 | 服务端加 `around`，客户端加载态 |
| R-25 | 分享快照独立成文件 | 同 R-20 类型的数据迁移 | 与 R-20 一起 |
| R-26 | 归档 54 个历史 QA 脚本 | 无功能风险，但会丢失历史证据 | 移到 `tools/qa/manual/` 并加 README |
| R-27 | 客户端「未保存」重试入口 | 服务端已上报 `persisted:false`，客户端只展示提示 | 加一条 banner + 重试按钮 |
| R-28 | 首页术语解释（Headless/DSH/标准） | 文案与信息架构决策，需产品判断 | 加一行图例或首次使用引导 |

## 不做（`WONTFIX`）

| ID | 事项 | 理由 |
| --- | --- | --- |
| W-1 | 引入框架/构建链重写前端 | 收益不确定、回归面巨大；现有零依赖约束是部署优势 |
| W-2 | 多租户账号体系 | 产品定位是单用户多设备；项目级 owner 隔离已覆盖已知越权 |
| W-3 | 为通过审计而删除 `role`/语义 | 语义保留，只调整 live 行为（见 ADR-004） |
