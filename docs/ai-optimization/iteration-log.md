## Round 1 · 正确性 / 稳定性 / 安全

**发现（节选）**：幂等键全局共享且校验前占用；PATCH 会话先写后校验；限流 Map 只增不减；原子写 `.tmp` 残留；
项目不是按 owner 隔离；未登录可吊销所有会话；中断下载泄漏 fd；最终 flush 失败丢回答；
坏记录导致启动崩溃或静默清库；64KB body 与 24k 字符矛盾；记忆满时静默淘汰；撤销分享仍占配额。

**修复**：20 项（`task-board.md` T1.1–T1.20）。

**验证**：新增 `isolation`（17）、`store-contract`（7）；`api` 增 5 条；全套件 20/20。

**遗留**：数据模型迁移、搜索索引、brotli、懒加载、深链定位、CSRF scheme、事件缓冲上限、run 启动 TOCTOU。

**下一轮依据**：导航竞态与可访问性问题在审计中占比最高，且用户可感知。

## Round 2 · UI / UX / 导航 / 可达性

**发现**：上传中切换会把气泡画进新对话（P0）；创建对话劫持导航；attach 回放泄漏；审批抢焦点；
禁用存储直接白屏；菜单 Escape 反而停止生成；幽灵气泡；跨会话草稿；慢加载覆盖输入；
重写指令被丢弃；叠层 Escape 关错层；回收站无焦点陷阱；打印摘掉在飞回答；移动菜单非模态；
320px 正文穿到透明顶栏下；标题永不显示；选中行对比度 4.40/4.11；触控 <44px；备份按钮竖排。

**修复**：13 组（T2.1–T2.13）。

**验证**：新增 `client-behaviour`（20 条真实浏览器断言）；用审计者自己的复现脚本复跑 `t1/t3/t4/t5/t6/t8` 对照；
重新测量对比度（4.81/4.80）、320px 顶栏与标题；`cycle1` 断言同步到新契约。

**过程中发现并修掉一个自己引入的回归**：批量替换 `document.activeElement` 时把 `focusOrigin()` 自身也替换了，
造成无限递归（打开"重新生成"弹窗抛 `RangeError`）。由 `client-behaviour` 捕获，修复后复跑通过。
教训：机械替换必须排除定义体，且**先跑测试再继续**。

**遗留**：首页术语解释；模型选择回滚（无法在沙箱复现）；观察器合并。

## Round 3 · 架构 / 性能 / 工程基线

**发现**：静态预算漏算 44KB（实际 303KB 被当成 258KB）；死 CSS（project chips 90 行）；
两个前端模块各 4s 轮询 + 观察 `#thread`；README 多处数字失真；85 个 QA 脚本中 54 个无人引用。

**修复**：预算从源码派生 + 孤儿样式表检查；删除死 CSS；轮询降为 15s 且后台标签页跳过；README 数字按实测更新。

**度量（只做基线，不宣称优化）**：见 `test-report.md` §4。关键结论：
- 真正的性能上限在**数据模型**（8.6MB 单文件、1000 会话 245ms 启动、满额外推 4GB RSS），不在 CSS/JS 体积。
- 因此把「一会话一文件 + 索引」列为独立迁移项（R-20），不在本轮顺手改。

**遗留**：R-20/R-21/R-22/R-23/R-24。
