## 2. 修了什么（按用户可感知的结果）

1. **不会再发错对话**：上传/创建/恢复生成三种竞态下切换对话，消息只属于它出发的那个对话；文本和附件回到你手里。
2. **不会再丢数据**：一条坏记录不再让服务起不来或静默清库；原文件先被备份；缺字段的记录被修复而不是让整页 500；
   落盘失败时界面会明确告诉你「没保存」，而不是假装成功。
3. **不会再越权**：项目按 owner 隔离（含备份导出、文件、权限继承）；未登录不能把所有人踢下线；
   文件 404 不再泄露服务器路径。
4. **不会再白屏**：浏览器禁用站点数据时仍能登录使用（只是不持久化）。
5. **不会再卡死**：断点切换不再留下 inert 页面；中断下载不再耗尽文件描述符；purge 不再阻塞整台服务器。
6. **可达性与可读性**：顶栏在 320px 滚动时有实底且显示会话标题；选中行对比度 4.81/4.80（原 4.40/4.11）；
   触控目标 ≥44px；手机操作菜单变成真正的模态层；Escape 只关最上层；审批不再抢焦点。
7. **工程可信度**：`npm run qa` 从 16/17 变 20/20；静态预算反映真实值（303KB/320KB）；
   README 的套件数、CSS 数、app.js 体积、导入去重描述都已按实测更正。

## 7. 部署与回滚建议

**部署**：无需迁移脚本，无接口契约破坏。
1. 备份 `data/`（尤其 `conversations.json`、`projects.json`）。
2. 拉取代码 → 重启服务（`launchd` 服务会自启；或 `./start.sh`）。
3. 首次启动会做一次性的「项目归属」（把无 owner 的项目归到 `single-user-owner`），幂等。
4. 冒烟：登录 → 新建对话 → 发一条消息（若桌面版在跑会走 native）→ 打开设置→最近删除 → 打开一个项目。

**回滚**：`git revert` 到 `43e3492`（本轮基线）即可；数据层没有破坏性变更，
新增的 `owner` 字段与 `.corrupt-*` 副本对旧版本无害（旧版本会忽略 `owner`）。
唯一需要注意的是：如果启动时发生过损坏隔离，恢复旧版本前请先确认 `.corrupt-*` 文件内容。

## 8. 后续优化路线（建议顺序）

1. **数据模型迁移**（R-20/R-25）：一会话一文件 + 索引 + 分享快照外置。这是后续所有性能工作的前提。
2. **搜索索引**（R-21）：与迁移同批。
3. **传输优化**（R-22/R-23）：brotli + codex 懒加载 + bootstrap 合并，目标冷载 ≤170KB。
4. **深链与分页**（R-24）。
5. **工程债**（R-26）：归档历史 QA 脚本，接入 CI（`run-all --quick` + `static`）。
6. **真机验证**（iOS 键盘/VoiceOver/PWA）与真实模型下的端到端。

## 9. 一句话总结

这一轮把「会丢数据、会发错对话、会越权、会白屏、会卡死」五类问题清掉，并用 47 条新断言把它们钉住；
性能只做了诚实的基线测量，没有拿体积数字冒充体验提升。剩下的最大风险只有一个——**单文件存储的数据模型**，
它已经被量化、被隔离成独立任务，而不是被忽略。
