# Round 3 · PM 验收

**结论：PASS（有条件）**  
回答从“只能整段重跑”变成“可重写、可手改、可回滚、可分叉、可对比”；分享从“整段默认发出去”变成“显式选段 + 服务端敏感拦截 + 可选口令 + 可更新”。
大项“访客身份、逐条脱敏、文件随备份、消息分页”按计划进入 Round 4–5。

## 1. 主链路

| 场景 | 结果 |
| --- | --- |
| 对回答说“更简洁，保留数字” | PASS（指令进入 prompt，旧版保留） |
| 改两个错字不重跑模型 | PASS（工具/思考块仍在，旧版进历史） |
| 回到上一版/并排对比/从这里分叉 | PASS |
| 只把两条消息发给客户 | PASS（默认 0 选，显式勾选） |
| 内容含手机号/邮箱 | PASS（服务端 409，二次确认） |
| 给链接加口令 | PASS（scrypt，错误口令 401） |
| 更新已发出的链接 | PASS（确认 + 重扫敏感） |
| 删除对话后链接失效/30 天内恢复 | PASS |
| 永久删除不残留 | PASS（分享/收藏/记忆/工作区/日备份） |
| 打印长对话 | PASS（120/120） |
| 英文提问 | PASS（英文脚手架） |

## 2. 残余风险

1. **分享仍是 bearer token + 可选口令**：没有访客身份、IP/域名限制；链接转发无法追踪到人。
2. **敏感信息只能整条排除**：不能对单个手机号打码；用户仍可能整段发出。
3. **大对话性能**：1.16MB 会话一次下发；消息级分页未做。
4. **备份不包含工作区文件**：迁移仍会丢附件/产出物。
5. **工程化**：app.js 约 1 万行；无 lint/typecheck/CI；QA 靠手工/脚本。
6. **HTTP 内网**：PWA/通知/语音不可用；需要 HTTPS。

## 3. 是否进入 Round 4

进入。Round 4 主题：**长内容、迁移与移动可用性**——消息分页、文件随备份、项目归档、早期编辑分支、性能与移动端打磨。
