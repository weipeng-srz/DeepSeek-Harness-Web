# R4 PRD：减少重复工作，处理并发与键盘边界

## 目标及评审
批准6项P2（P0/P1/P3 0），未到50，保留真实复现。跨标签页P1已提前纳入R3。本轮不能把本地暖缓存结果包装成真实用户Core Web Vitals。R3验收后才实施。

## 需求
### R4-001 · P2 · CSS缓存命中仍重复读取全部七文件
- 场景/角色：工程/日常用户希望页面状态与最新操作一致并可恢复失败。
- 当前表现/证据：backend-R4-baseline.json：100次暖缓存200或304各读取700次共21.9MB。
- 修改与验收：先stat计算key，仅未命中读取/压缩；内容修改正确失效；gzip/ETag/304行为相同；暖缓存100请求内容读取0次。
- 范围：server/index.mjs；风险：仅减少重复I/O，不能据此宣称首屏快若干倍。
- 验证：独立HTTP I/O计数与真实Chrome故障注入；同一用例验证修复前后。

### R4-002 · P2 · 文件预览旧请求污染新的文件或关闭后的容器
- 场景/角色：UX/文件用户希望页面状态与最新操作一致并可恢复失败。
- 当前表现/证据：R2 advanced：A延迟1秒→关A开B，B正文出现B+A；关闭后也追加。
- 修改与验收：每次打开/关闭作废请求；文本用AbortController，慢A不能改B/关闭视图；图片错误状态也只属于本次；焦点及下载链接匹配当前文件。
- 范围：public/js/app.js；风险：取消只终止预览读取，不取消生成或上传。
- 验证：独立HTTP I/O计数与真实Chrome故障注入；同一用例验证修复前后。

### R4-003 · P2 · 公式资源一次加载失败使同页永久无法渲染
- 场景/角色：工程/内容阅读用户希望页面状态与最新操作一致并可恢复失败。
- 当前表现/证据：R2 recovery：本地/vendor/katex JS首请求故障后下一公式仍仅一次请求，0个.katex。
- 修改与验收：失败后清除失败promise与元素，下一次公式请求可重试；并发只加载一次；失败保留可读原文，成功后公式正常。
- 范围：public/js/app.js；风险：无新CDN，不无限后台重试，不重复注入CSS。
- 验证：独立HTTP I/O计数与真实Chrome故障注入；同一用例验证修复前后。

### R4-004 · P2 · 分页旧响应混入新搜索结果
- 场景/角色：工程/搜索用户希望页面状态与最新操作一致并可恢复失败。
- 当前表现/证据：R2 recovery：Alpha加载更多延迟，改Beta后仍混入10条Alpha并错误计数70。
- 修改与验收：分页捕获查询和版本；查询变化或刷新时旧响应不能改结果/计数/hasMore；加载按钮可恢复；同查询正常追加去重。
- 范围：public/js/app.js；风险：保留原列表分页和全文API，查询A-B-A也需防旧请求。
- 验证：独立HTTP I/O计数与真实Chrome故障注入；同一用例验证修复前后。

### R4-005 · P2 · 设置单选组宣称radio却没有箭头键行为
- 场景/角色：UX/键盘用户希望页面状态与最新操作一致并可恢复失败。
- 当前表现/证据：R2 advanced：theme/density/font按ArrowRight均不变。
- 修改与验收：统一radio键盘：方向键循环，Home/End首尾，单一tabstop，禁用选项跳过；主题/密度/字号点击与持久化仍正常；引擎组同语义且禁用不可选。
- 范围：public/js/app.js；风险：不改变引擎业务；组内切换焦点不能逃出弹窗。
- 验证：独立HTTP I/O计数与真实Chrome故障注入；同一用例验证修复前后。

## 状态和交互规范
请求：开始记录归属→等待→仅最新版本提交；关闭/改变查询作废旧版本。失败应保留已有可读内容或给出明确恢复动作。公式失败清理后由下一次内容阅读触发重试。
Radio：Tab进入选中项，Arrow/Home/End选择与聚焦，Tab离开组；兼容现有pointer点击与aria-checked。动效尊重减少动态效果，功能反馈无需动画才能理解。

## 研发分工/依赖/回归
后端agent负责CSS bundle与缓存回归；frontend负责preview、math、分页三函数区；主agent负责radio行为。QA拥有advanced/recovery/主套件，产品逐项验收。
不迁移数据，不替换存储或引擎；回归备份、文件列表/预览、公式、长消息DOM、导航/搜索/草稿、模态与主题；边界含离线失败、取消、A-B-A查询、重复按键。真实物理设备/长时间模型流式内存与现场网络仍需后续独立采样。

## 新发现 R4-006 · P2 · 阅读偏好刷新丢失

QA在验证R4-005持久化时实测紧凑密度和大字号刷新后未保留。loadPrefs在state初始化中早于PREFS_KEY常量声明执行，错误被catch后回到默认。新用户/日常用户无需每次重复设置。将同一存储键前置初始化，不迁移数据；分别点击/键盘更改、刷新、非法存储回退验证。根因与radio键盘独立，单独跟踪，主agent实施。
