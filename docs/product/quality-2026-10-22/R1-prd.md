# R1 PRD：核心功能与数据可信性

## 迭代目标与评审

基于当前运行版本、18个功能模块清单和独立后端/前端审计，本轮批准11项有效需求（P0 1、P1 9、P2 1、P3 0）。未达到目标50项，不将同一缺陷按按钮、主题或屏幕拆成多项。其他有证据候选进入后续轮次。基线源码已由QA固化到独立服务，避免“修复后反推基线”。

产品经理决定先处理可能丢数据、误导操作结果和核心导航失效的问题。需求是对现有能力的修复，不新增复杂产品概念。

## 交互与状态设计

- 会话导航：用户选择 → 加载骨架 → 仅最新请求提交 → 内容/路由/草稿一致；失效请求无副作用；失败恢复此前可操作界面并提示。
- 批量操作：选择 → 忙碌（防重入）→ 成功集合/失败集合 → 精确结果；失败项保留供重试；撤销只处理成功集合。
- 导入：解析 → 完整校验与容量检查 → 构造新对象 → 一次提交；任何错误回到未改动状态。
- 模态：是否阻止背景由实际可见模态层决定，重复打开不累计锁；焦点应可恢复。
- 错误提示沿用现有Toast/inline语义，明确发生了什么和下一步；不以技术栈名代替用户指引。

## 非功能、边界和回归

保持访问码、同源限制、只读/标准/完全权限映射、流式后台继续、现有JSON数据格式。验证同名上传、空/非法备份、超过容量、连续快速导航、网络失败、重复快捷键及已打开弹窗。不可仅凭源码判通过。现有DSR兼容修复是基线，不计作本轮新增。

## 研发分工及依赖

后端agent负责store/index/start/deploy与后端回归；前端agent仅负责batch函数区段；主agent负责auth、导航和overlay函数。QA拥有独立浏览器脚本，先基线后对新副本重跑。完成后产品经理按requirements.json逐条核证，失败返回研发。没有数据模式迁移；必要时从初始代码快照回退，用户数据不回滚覆盖。
