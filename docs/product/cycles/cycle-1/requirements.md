# DSH Chat 产品需求文档 · v3.0（50 条总需求池）

> **v3 总需求池（50 条）**：本文件是原始需求池与验收口径。实际交付拆分为 5 轮、每轮 10 条；轮次映射与最终结果见 `docs/product/v3/00-master-prd.md` 与 `08-traceability.md`。

> 主题：**可信赖的日常使用**（Trustworthy daily driver）
> 输入：`user-trial.md` 的 20 条用户观察 + 代码/接口审计
> 目标：让用户「找得回、改得了、删不慌、断不了、看得见」；不改变核心架构与视觉语言。
> 参考：ChatGPT（消息操作/草稿/重新生成）、Claude（工具过程可读性）、Linear（命令面板/撤销）、Things（置顶/分组）、Apple HIG（44pt 触控/降低动态/对比度）。

## 0. 目标与非目标

**目标**
1. 所有「会丢东西」的操作都可恢复：草稿、删除、断网发送。
2. 高频动作 ≤ 2 次点击：重命名、置顶、重新生成、编辑重发、上传。
3. 会话可被找回：标题 + 正文全文搜索、预览、消息数、置顶。
4. 移动端单手可用：触控目标 ≥44px、键盘不遮挡、无横向滚动。
5. 让等待与失败可解释：骨架屏、进度、重试、错误边界。
6. 性能不倒退：静态 gzip/ETag、会话分页、流式渲染保持。

**非目标**
- 多用户/账号体系、云同步、公开分享链接。
- 消息分支树（本轮只做「编辑后覆盖后续」）。
- 端到端加密、附件内容扫描（只做类型/大小/路径校验）。
- 视觉大改版；新增样式统一收敛到 `refine.css`。

## 2. 交互与视觉约束

- 新增组件沿用现有 token；新增样式集中在 `public/css/refine.css`，不改动既有四套样式的主体。
- 会话菜单/用量浮层/命令面板：圆角 16px、细边框、轻阴影；`--surface` 背景；不叠加 blur。
- 所有动效 160–260ms，`cubic-bezier(.22,1,.36,1)`；`prefers-reduced-motion` 下时长 1ms。
- 移动端 ≤640px：菜单改为底部 sheet；桌面为锚定浮层。
- 文案：短、动词开头；错误说明「发生了什么 + 怎么办」。

## 3. 数据与接口变更

| 接口 | 变更 |
| --- | --- |
| `GET /api/conversations` | 支持 `q`、`limit`、`before`；返回 `pinned`、`preview`、`messageCount`、`hasMore`、`total` |
| `PATCH /api/conversations/:id` | 支持 `pinned`；`title` 允许清空校验 |
| `DELETE /api/conversations/:id` | 改为软删除，返回 `undoUntil`；新增 `POST /api/conversations/:id/restore` |
| `POST /api/conversations/:id/chat` | 支持 `retryOf`（重生成）、`editOf`（编辑重发）、`attachments`、`Idempotency-Key` |
| 消息模型 | 用户消息新增 `attachments: [{path,name,size,kind}]` |
| 静态资源 | gzip/br、ETag、immutable 缓存 |

## 4. 验收门槛

- P0 全过，P1 ≥90%；无 S1/S2 缺陷；控制台 0 报错。
- 390×844 无横向滚动，可点元素 ≥44px（视觉图标可小）。
- 断网/停止/刷新/删除撤销四条恢复链路全部通过。
- 首屏 CSS+JS 传输体积较基线下降 ≥30%（gzip 后），会话列表首屏 ≤60 条。
- 真实发一条消息、上传一个文件、重生成一次、编辑重发一次全部通过。
