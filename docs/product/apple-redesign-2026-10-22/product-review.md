# Apple 风格重设计：独立产品与工程审查

审查日期：2026-10-22。角色：Apple 工程、UX、产品验收。状态：重设计前基线完成，重设计后复验待最终样式冻结。

## 结论与范围

现有核心任务路径已经可用。本次视觉重设计应优先改善小字、触控目标、层次和材质一致性，保持场景一键填入、搜索正文、完整会话菜单、权限说明和设置入口。没有证据支持为视觉简洁而删减功能。

实际验证使用独立 Node 22 HTTP 服务、Chrome 155、1440×1000 桌面和 390×844 手机模拟视口。服务端、静态资源、会话和凭据目录均为隔离副本；没有调用真实模型、修改用户数据或重启主服务。这是模拟用户任务检查，不是真实用户研究；手机视口不能代替 iOS Safari 和软键盘实机验证。

基线源固定为 `reports/quality/apple-before/results.json` 记录的源快照，避免与并行样式修改混淆。专项脚本：`tools/qa/quality-apple-product.mjs`；原始证据：`reports/quality/apple-product-before/product-review.json`。每项结果包含源文件哈希、尺寸与字体测量、截图路径。

| 编号 | 优先级 | 当前表现 / 证据 | 建议与验收 |
| --- | --- | --- | --- |

| A-UX-02 | P2 | 侧栏收藏/提示词高 32，管理/归档高 28，连接入口高 34；手机展开侧栏后沿用这些尺寸 | 对触控可见入口采用至少 44 高；扩大点击区域，不只是放大图标；保持侧栏列表可滚动、底部偏好不覆盖会话 |
| A-UX-03 | P2 | 普通场景说明 11px、权限说明 11px、设置说明 11.5px、会话时间 10.5px；文本直接影响任务/权限理解 | 主要说明建议 13px 起、自然行高，元信息至少 12px；手机卡片允许自然增高，保留“需要”信息，避免固定高度截断 |
| A-UX-04 | P2 | 首页由彩色光球、多色卡片、图形和彩色输入边缘同时吸引注意，输入为最下方主要任务入口 | 用中性表面和单一蓝色强调；场景保持一键填入与可编辑，不新增中间确认；新视觉必须让输入和示例都容易发现 |
| A-UX-05 | P2 | 手机首页卡片说明已经换行，但卡片下方仍有较大空白 | 优先把空间用于可读说明与稳定输入区；不要把更多内容压成更小字；320/390/768 均无横向溢出，长草稿与附件不会遮挡发送 |
| A-UX-06 | P2 | 桌面会话菜单 9 项完整，删除独立分隔；菜单已可点击，视觉阴影较重 | 保持顺序、危险项分隔、键盘焦点和关闭行为；只统一字体、材质与阴影，菜单不得因更窄尺寸截断标签 |
| A-UX-07 | P2 | 设置、权限、Codex 模型面板来自不同 CSS 层；设置说明与权限说明字号不一致 | 统一面板背景、分隔线、标题、44px 关闭目标、focus-visible；保留 aria-modal / inert / Escape / 焦点返回机制 |
| A-UX-08 | P2 | 旧版七层 CSS 中共有 78 个 `!important`，同一 composer/topbar/sheet 被多次覆盖；多处 backdrop-filter 声明不等于实际同时模糊，但增加覆盖判断成本 | 使用唯一最终设计文件，按组件列出覆盖边界；对真实 blur/阴影逐项审查，不为“玻璃感”叠加多个大面积滤镜；不得删除隐藏状态或滚动约束来消除截图问题 |

44px 是本轮舒适触控目标，不应把所有低于 44px 的元素直接标记为 WCAG 失败。WCAG 2.2 AA 的目标尺寸最低值是 24×24 CSS 像素，同时存在间距等例外；这里尚未做完整相邻命中区域认证。[W3C 对 2.5.8 的解释](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

设计依据使用本机 `apple-design/SKILL.md`：清晰任务层次、响应反馈、空间关系、克制材质、系统字体和减少动态效果。没有宣称复刻 Apple 产品或通过 Apple 官方验收。

## CSS 集成与回归方案

根层确认采用 `public/css/design-system.css` 作为唯一第 8 层，`html[data-design="apple"]` 为设计作用域。旧 `apple.css` 继续只加载一次。Codex 的独立 `codex.css` 由前端负责人统一。此审查未修改产品源码。

1. **资源唯一且顺序明确。** bundle 列表最后加入新文件；不把旧 `apple.css` 再追加一次。最终新 CSS 应位于全部旧视觉层之后。由于旧 `!important` 仍然优先于普通声明，需要明确处理具体冲突，不能假定文件最后就能覆盖一切。
2. **不改变状态契约。** `[hidden]`、`.is-open`、`.is-sheet`、`.active`、aria-selected / aria-checked / disabled / focus-visible 和 `[inert]` 的既有语义保持。不要用全局 `display: flex` 覆盖隐藏菜单，也不要给覆盖层设置穿透点击。移动抽屉与桌面侧栏的 breakpoint 继续与 JS 一致。
3. **集中变量。** 明暗背景、主/次文本、分隔线、蓝色强调、危险色、阴影、圆角、字体与行高集中定义；运行状态不能只凭颜色。主题自动模式、显式 dark/light、字号/密度设置均需复验，防止新变量把用户阅读偏好锁死。
4. **动画可退出。** 简单按钮、菜单不需要新物理引擎。以 opacity / transform 为主，保留 reduced-motion；不增加为完成动画而阻塞关闭的逻辑。大面积模糊要检视实际层级和滚动性能。
5. **缓存版本成组更新。** 修改 bundle 版本与相关 SW 缓存版本；Codex 动态 CSS 自己的版本由其负责人更新。旧安装客户端升级和离线回访按已有 release 测试真实验证，不能只测试无 SW 的新页面。
6. **功能回归必须真实执行。** 先复跑本专项 10 个任务；再以已有 quality-cycle / features / exploration / design / release / Codex modal 等脚本覆盖上传、下载、导入导出、搜索、重命名、归档、复制、草稿、错误恢复与多层模态。只有实际运行的项目可记通过。
7. **视口与缩放。** 至少 320/390/768/1440、明暗主题、200% 缩放、减少动态效果。手机验证应额外检查底部安全区、滚动后的菜单、横向超长文本；iOS Safari 软键盘仍需实机补测。

## CSS 缓存专项的适配与基线

已更新 `tools/qa/quality-css-cache.mjs`，按生产 `CSS_BUNDLE_FILES` 实际清单计数，并断言清单非空且无重复。没有硬编码为 8 而弱化内容验证：

- 冷缓存必须读取每个真实资源恰好一次、压缩一次，解压后的字节必须与清单顺序拼接完全一致。
- 100 次暖 200 和 100 次 304 分别要求 **0 内容读取、0 压缩**，每次仍检查全部资源 stat。
- 对清单中的**每一个**文件做同大小内容修改并更新 mtime：必须新 ETag、200、新内容完全匹配、整包只重建一次；随后 304 不读取内容。这比原先只改 `style.css` 覆盖更多失效路径。
- 最后一层文件缺失必须 500，恢复后 200 且完整内容一致；验证 HEAD、identity 与未带版本时的 no-cache。

七层旧版实跑 6/6 通过：原始包 219,154 B、gzip 36,405 B；两组 100 请求均 0 内容读取、0 压缩，各 700 次 stat。证据：`evidence/apple-cache-before.json`。本地 HTTP 耗时只用于确认缓存行为，不能表述为首屏或 Core Web Vitals 提升。第 8 层加入后需要再次执行，届时 stat 预期为每 100 请求 800 次。
